# Linux x86-64 图形版与无图形版

## 目标与边界

面向 Ubuntu/Debian x86-64，交付 Linux 图形程序和不依赖图形环境的命令行程序。两者使用本仓库现有 EasyConnect、UniVPN、TopSAP 引擎，保留已有平台兼容。用户希望最终通过 GitHub Release 下载同一提交的各端产物；构建、模拟网关、真实系统 TUN 和真实网关结果分别记录，不能保证不存在所有缺陷。

## 已确认的现状

- Wails Linux 图形二进制及上游 `zju-connect` 命令可在 GitHub Linux runner 编译；后者支持的协议和配置与桌面引擎不同，不能冒充 Suite 完整无图形版。
- Linux 的 GUI 配置使用 XDG 配置目录，默认关闭桌面 TUN、开启本地代理；现有桌面 TUN 权限、IPC、系统路由与 DNS 不支持 Linux。底层上游 TUN 代码不等于桌面多会话资源分流实现。
- TopSAP 的 Linux 设备身份尚未验证；现有 Windows 和 macOS 身份生成方法不同，不能猜测 Linux 身份或伪造设备信息来声称兼容。
- 无真实网关时，只能以模拟网关证明客户端实现与测试协议的交互，不能证明真实网关及其设备策略兼容。

## 实现和验收

1. 无图形版使用与 GUI 相同的引擎和配置语义，明确连接、状态、退出和密码输入方式；不将密码或 TOTP 放入命令行、日志或测试资料。测试覆盖各协议实际支持范围、认证拒绝、代理流量及信号退出清理。
2. Linux 图形版验证 Ubuntu 环境下启动、配置持久化、多个连接和代理流量，明确桌面依赖；不声称未经验证的托盘兼容。
3. 实现 Linux TUN 前设计所有权、独立权限、路由与 DNS 原子更新、冲突与崩溃清理，测试须包含真实 Linux 网络命名空间和模拟网关的 TCP/UDP 转发；记录受限脱敏的操作/阻塞证据，避免修改或删除其他 VPN 的资源。
4. 通过 GitHub Actions 为同一提交运行 Linux、Windows、macOS Intel/ARM 和 Android 的构建及既有测试；收集各平台产物，Release 写明架构、依赖、已验证与未验证范围。
5. 真实网关验证和设备身份必须有授权环境与证据；不可通过模拟测试代替，也不可将 x86-64 产品称为 32 位 x86。

## Linux TUN 设计草案（尚未实现）

- 图形客户端保留普通用户权限，认证、资源策略、代理和连接管理继续位于现有引擎。需要系统分流时，经 `pkexec` 启动独立 TUN Worker；授权失败、缺少 polkit 或图形授权代理时明确报错。无图形场景必须另行明确受控授权和生命周期，不能依赖图形授权弹窗。
- 使用 /tmp 中随机命名的独占私有目录和 Unix socket，目录权限为 0700，并验证目录所有者和对象身份，通过 `SO_PEERCRED` 验证连接双方的 PID、UID 与实际 Worker 身份。沿用现有带会话、附件和策略版本的 IPC 协议，Worker 不接收密码、配置文件路径或未经策略验证的目标。
- Worker 为每个附件创建独立 TUN，按服务器授权的 IPv4 资源前缀安装路由；不添加默认路由，不覆盖已有 VPN 的相同路由。通过 Linux 网络接口与路由 API 校验创建和删除对象的身份；更新必须先校验冲突，失败时回滚本次变更并报告残留。
- DNS 分流需要按链路的 DNS 路由和归属验证；首发只在能够正确识别并管理 DNS 服务的系统上启用，具体支持 systemd-resolved 的方法和冲突语义须以集成测试确认。不可直接改写其他连接的配置或在清理时恢复过期的全局配置。
- 父进程退出、IPC 断开或 Worker 异常时，清理只针对本附件拥有的网卡、路由与 DNS 状态。无法确认清理成功时禁止自动重新附加；重连沿用现有连接身份、取消、阻塞诊断及有界恢复契约。
- 验证计划：在隔离网络命名空间内运行真实内核 TUN 和路由，使用模拟网关检查 TCP、UDP、DNS，覆盖重连、授权失败、冲突、崩溃、残留和其他 VPN 共存；另行验证 Ubuntu/Debian 上 polkit 与桌面 DNS 集成。命名空间成功不等同于真实网关或全部发行版兼容。
