# 会话交接设计与待验证问题

## 已确认的风险
- 服务线程读取共享 wantConnected：旧线程在停止后若看到同实例的新启动把它重新设为 true，可能继续重试或清理新会话。
- connectOnce 的 finally 无条件清空共享 tunnelFd，随后根据共享 wantConnected 决定调用进程级 Mobile.logout；这两个操作与新会话建立可能交错。
- Mobile.logout 和 Mobile.stopStack 是进程级操作。单独检查会话 ID 后再调用它们仍有检查与调用之间的竞态；service onDestroy 也可能跨服务实例影响共享状态。
- 登录过程存在串行锁和取消代号；排队与取消的顺序必须覆盖，不能假设调用线程中断会立即取消 Go 网络调用。

## 关闭路径的实际阻塞边界
`TunnelService.stopTunnel()` 和 `onDestroy()` 在 Android 主线程同步调用 `Mobile.logout()`。`Logout()` 释放 `vpnClientMu` 后同步调用 `Client.Close()`；后者先取消生命周期，再等待 `setupMu`，然后关闭保留连接。当前代码没有为该主线程等待设置上限。仅从源码可确认存在同步等待，不能据此认定已发生 ANR 或量化等待时长。

迁移时不能只是把现有 `Mobile.logout()` 放进任意后台线程：如果新登录先于该线程执行，旧线程会关闭新客户端。应让全局会话拥有单一交接屏障，令新登录在前一会话的取消请求、客户端关闭和 TUN 清理全部返回后才开始；等待不得占用主线程。即使取消了正在排队的中间会话，后续请求也必须仍等待其前序清理。关闭操作的等待和结果应有会话身份与可定位的阻塞证据。

## 设计约束
需要将进程级会话所有权的交接与全局清理作为一个可序列化的操作：旧会话撤销后，新会话的登录必须等旧会话的客户端与隧道清理完成；等待发生在后台线程。停止可以并发中断当前阻塞操作，不能因等待锁导致无法取消。服务回调的状态更新、描述符登记/移除和终止服务均应校验对应会话的所有权，且检查与修改须原子执行。跨实例清理必须识别所有者，不能让旧实例关闭新实例。

交接、取消和清理需包含连接/操作身份、阶段、耗时、取消及错误；对阻塞路径按项目日志契约保留受限脱敏线程证据。不在日志中记录账号、凭据、地址或报文。

## 取消序号不是会话所有权
`logoutGeneration` 只由 `Logout()` 递增；同一登出序号下可以依次进入多个登录请求。`LoginEpoch` 因此只能判定请求在捕获序号后是否发生过登出，不能用作 `LogoutForEpoch` 或 `StopStackForEpoch` 的所有权判断：旧请求和新请求可能拿到相同值，旧请求就会误关闭新请求。

完整接口需要独立的、每次用户连接请求唯一的身份。请求身份与客户端、TUN 的归属必须在同一同步边界内登记和摘取，关闭只能操作摘取到的旧对象；不能先检查身份、释放锁，再通过无身份的全局 `Logout()` 或 `StopStack()` 查找当前对象。登录取消序号仍用于覆盖调用入口前的取消窗口，不替代会话身份。

## 确定性交错测试
1. 旧登录在返回前暂停；停止旧会话并启动新会话，释放旧登录，验证旧结果不会建立 TUN、发布状态或取消新会话。
2. 旧 TUN 返回后在清理前暂停；新会话请求启动，验证新登录等待旧清理完成，再验证旧清理不会关闭新客户端或描述符。
3. 新会话等待交接期间取消；释放旧会话后验证新登录从未执行、没有重试及状态回退。
4. 旧服务实例延迟销毁且新实例请求启动，验证进程级清理与状态更新不跨所有权。
5. 认证拒绝和正常断线退避保持原行为；用模拟器执行快速启停和 TCP/UDP 往返。

实现前需将操作的同步边界和可注入测试接缝落实到真实服务及 Mobile 层；只测试独立状态模型不能证明真实清理安全。

## 当前实现的验证边界

工作线程已接入交接屏障。停止请求在独立清理线程关闭请求登记的 TUN 描述符、客户端和转发栈，工作线程等待该清理返回后才释放后继；等待交接时取消的请求不拥有客户端，不执行进程级清理。`SessionCleanupTest` 控制清理阻塞，验证停止返回、完成屏障和清理失败；`TunnelServiceHandoffTest` 使用可控客户端直接运行服务，覆盖旧登录与旧清理延迟、新请求等待及旧结果不覆盖新状态。该服务测试尚待工作流验证，也不能替代 TUN 描述符及服务实例延迟销毁的受控测试。

状态发布按进程内当前请求身份和取消标记过滤，并用递增版本抑制已排队的旧回调。终止与通知现由主线程执行，并在执行前校验请求身份；TUN 转发入口持有独立描述符副本直到调用返回，避免服务描述符被取消关闭后编号重用。已新增直接运行服务的受控测试，暂停旧转发、取消旧请求并启动新请求，验证交接等待和旧转发入口描述符在取消后仍有效；测试结果尚待构建验证，描述符泄漏和实际设备表现仍需独立检查。Java 侧交接和清理等待已接入观察器：超过 30 秒记录请求、操作、线程、阶段和取消状态，并向 logcat 输出限量线程栈；栈不包含线程名称或方法参数。阻塞证据同时写入应用私有目录，文件按 256 KiB 轮转并保留一代；正常未阻塞的等待不写入此文件。已添加文件轮转和真实服务阻塞时脱敏持久化的测试，测试结果及设备上的保留行为仍待验证；不能假设 logcat 长期保留。

模拟器的空闲心跳与 CPU tick 只能描述对应测试窗口，不能证明真实设备电量、后台保活或真实网关兼容性。各项结论须以同一提交的实际测试结果为准。
