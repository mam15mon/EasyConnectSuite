# 多 VPN 状态归属修复

## 目标与价值

消除验收发现的三个 P2 问题，使多 VPN 工作台在重试、快速切换和启动失败时，始终显示所选配置及当前会话的数据，且不影响其他连接。

## 背景与证据

审查基线为 main 合并提交 c5f630ee3013c09a8f7afe9668ea5d2607a3f705（2026-10-12）。以下问题均有受控复现，详见 research/acceptance-evidence.md。现有测试和生产构建通过不代表这些业务时序已被覆盖。

## 需求

### R1 — 旧启动结果不得覆盖当前会话（P2）

- 位置：connections.go:240–256，重点为 :250–254；回调已有的身份检查位于 connectionStatus / connectionResources。
- 复现：旧启动先报告失败但延迟返回；同一配置重试成功后旧启动返回错误。GetConnections 显示 connected / 192.0.2.22，GetStatus 却变为 error / 空 IP。
- 旧请求的返回、回调和资源只能属于旧会话；新会话的状态、IP、资源与停止能力不受影响。
- 旧请求结束及取消等待必须正常完成；不得以禁用重试或新增自动重试掩盖问题。
- 同时验证 frontend/src/main.js:609–613 对启动返回字符串的处理，防止界面重新发布过期错误。这是同一问题的关联风险，尚未单独复现。

### R2 — 资源始终属于明确选择的配置（P2）

- 位置：frontend/src/main.js:698–709，重点为 :706–709；选择排队位于 :417–418；app.go:430–437 提供按后端当前选择读取的接口。
- 复现：前端选择 B、后端选择队列仍停留 A，此时刷新将 A-resources 缓存并显示在 B 下；队列完成后才恢复 B。
- 快速 A→B→A、选择等待期间刷新、延迟响应及状态事件交错，均不得显示其他配置的资源。
- 对已知但无会话/已断开/失败的配置显示空资源；未知配置明确报错，不读取当前选中项代替。
- 选择和刷新不得启动、停止或切换其他 VPN 会话。

### R3 — 日志目录失败仅回滚本次启动（P2）

- 位置：connections.go:229–235，重点为 :232–233。
- 复现：选中 A，启动 B，将日志父目录设为测试用普通文件使 MkdirAll 失败；ActiveProfileID 仍为 A，GetStatus.ProfileID 却变为 B。
- B 启动失败后，A 的选择、状态、资源及运行连接保持一致；B 不得残留 connecting 或占用启动名额。
- 若失败的是所选配置，则其详情回到明确的非运行状态并清空旧资源；保留原始错误，不能换目录或静默忽略失败。

## 约束与边界

- 最小修复，不添加兜底、替代目录、自动重试、通用状态框架或无关重构。
- 保持深信服旧配置、三协议配置结构、证书选项、端口分配及托盘按 ID 操作兼容。
- 不改协议报文、认证算法、实际路由/DNS 策略、外观和持久化格式。
- 每次命令修改项目文件后，仅提交本次改动；只读检查不创建空提交。
- 测试使用临时目录、模拟引擎、受控 Promise 和脱敏数据；凭据、真实配置、私有日志不得进入 Git。
- 本次请求交付规划文档；产品修复、推送与发布不在本轮执行范围。

## 验收标准

- [ ] AC1 / R1：旧启动失败晚返回后，当前会话的列表、详情、IP 和资源一致；旧请求和取消等待可结束，新会话可独立停止。
- [ ] AC2 / R1：前端接收到过期启动结果时不会把当前成功会话改成失败；当前请求的实际失败仍可见。
- [ ] AC3 / R2：后端尚未完成选择时刷新 B，只能显示 B 的资源或空状态；快速切换、逆序响应和事件交错都不串配置。
- [ ] AC4 / R2：已断开配置返回空资源，未知 ID 明确失败，查询不改变活动选择，也不影响会话。
- [ ] AC5 / R3：选中并运行 A、启动 B 时模拟目录错误，A 全部状态保持一致；B 无残留连接且错误可见；选中项自身失败时资源清空。
- [ ] AC6 / 全部：新增确定性回归在修复前失败、修复后通过；现有连接隔离、取消和托盘测试继续通过，根及相关嵌套模块 test/vet/race、前端检查通过。
- [ ] AC7 / 全部：Wails 绑定、预览 API 与生产资源同步；未压缩 Windows 构建成功，脱敏 UI 复验通过，记录提交、文件大小及 SHA-256。

## 验证边界

本任务仅以代码、模拟测试、浏览器脱敏预览及 Windows 构建验收。真实网关兼容、真实 UDP、长期稳定性、实际休眠恢复和多厂商 TUN 共存继续保留在既有 TopSAP 任务中，不能由本次通过推导为完成。无阻塞规划的产品问题；实施前须审阅本计划。
